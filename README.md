# speciai.team 네이버 블로그

블로그: **https://blog.naver.com/speciai_**

검색에서 걸리는 글을 만들어 발행하고, 실제로 몇 위에 걸렸는지 추적합니다.
소재 발굴 → 경쟁 분석 → 글 → 이미지 → 발행 → 순위 측정까지 한 폴더 안에 있습니다.

---

## 글 한 편 내는 순서

```bash
cd ~/Work/speciai/speciai.team/blog

# ① 뭘 쓸지 고른다 — 오래된 글이 상위를 지키는 키워드가 기회입니다
open research/전략.md

# ② 초고를 쓴다 (웹 검색으로 현행 법령을 확인합니다. 3~5분)
node generate.mjs "접대비 한도" --cat 세무

# ③ 본문 이미지를 만든다 (마커 자리마다 카드 20장 + 발행본)
node cards.mjs posts/2026-08-04-접대비-한도.md

#    한 주제를 여러 편으로 썼다면 서로 묶습니다
#    node series.mjs 취업규칙 posts/A.md posts/B.md posts/C.md

# ④ 원장에 등록한다
node rank.mjs --add posts/2026-08-04-접대비-한도.md

#    ─── 여기서 사람이 검토하고 네이버에 발행합니다 ───

# ⑤ 발행 주소를 원장에 알린다
node rank.mjs --publish 2026-08-04-접대비-한도 https://blog.naver.com/speciai_/223...
```

⑤까지 하면 **매일 아침 9시 30분에 순위가 자동으로 측정**됩니다.

---

## 발행 전에 반드시

**초고는 초고입니다.** 법률·세무 글이라 틀린 수치 하나가 신뢰를 깎습니다.

1. 글 맨 위 `checks:` 항목을 전문가가 확인합니다
2. 본문에 `[확인 필요: ~]` 가 남아 있으면 채우거나 문장을 들어냅니다
3. 조문 번호와 금액이 현행인지 대조합니다 — 세법·노동법은 매년 바뀝니다

발행을 자동화하지 않은 이유가 이것입니다.

| `원고생성.mjs` | **여기 블로그 글이 아닙니다** — 제휴 커뮤니티 채널에 실을 짧은 원고를 뽑습니다. 재료는 `_공용/gov-support` 공고 원장, 결과는 `../community/원고/`. 지원사업 소재가 3건이 안 되면 표를 빼고 규제 3건으로 갑니다(1,400~1,800자 / 표 없으면 1,800~2,200자). 규격과 이유는 [콘텐츠구성 v1](../community/기획/콘텐츠구성_v1.md) |

## 지금 진행 중인 실험 — 규칙 1판 vs 2판

**2026-08-09에 글쓰기 규칙을 2판으로 갈아엎었습니다.** 상위 노출 1,004건을 순위 기준으로
다시 분석해서 초판의 네 항목을 뒤집었습니다 (문단 46자 · 소제목 5~6 · 이미지 15 ·
검색어를 통째로 쓰지 않기). 자세한 근거는 `research/글쓰기-규칙.md` 와 `research/순위분석.mjs`.

**다만 2판은 아직 «가설»입니다.** 상위 글을 관찰해 세운 것이지 우리 글로 검증한 게 아닙니다.
짝비교에서 통계적으로 유의했던 건 소제목 하나뿐이고, 나머지는 상위권 실측일 뿐입니다.

그래서 **이미 1판으로 쓴 초고 4편을 다시 만들지 않고 비교군으로 남깁니다.**
검토 34건이 이미 정리돼 있어 다시 만들면 그 작업이 날아가고, 무엇보다
**두 방식의 순위를 실제로 대조할 기회**가 사라집니다.

| | 규칙 | 글 | 실제 모양 |
|---|---|---|---|
| 비교군 | 1판 | 초고 4편 | 문단 78~97자 · 소제목 7~8 · 이미지 17~21 |
| 앞으로 | 2판 | 다음 글부터 | 문단 46자 · 소제목 5~6 · 이미지 15 |

원장(`ledger.json`)의 각 글에 `ruleset` 과 발행 시점의 `shape` 가 박힙니다.
**규칙을 지켰는지가 아니라 실제로 어떤 모양이었는지**를 남기는 이유는, 규칙이 틀릴 수 있고
답은 순위에만 있기 때문입니다. 판마다 순위 붙은 글이 2편 이상 쌓이면
`node rank.mjs --report` 아래에 판별 성적이 나옵니다.

**규칙을 또 고치면 `rank.mjs` 의 `RULESET` 을 같이 올립니다.**

## 알아둘 것

- **디스코드는 `#비서-알림` 하나로 모읍니다.** `blog/.env` 의 웹훅은 `_공용/report`·`gov-support`·
  `assistant` 와 같은 주소입니다. `.env` 는 저장소에 안 올라가니 새 기기에서는 다시 넣어야 합니다.
  값이 비면 알림은 콘솔 미리보기만 하고 cron 은 그대로 돕니다.
- **crontab 은 `crontab -` 로만 고칩니다.** `crontab 파일경로` 는 기존 것을 조용히 다 지웁니다.
  카드뉴스·정부지원사업 등 다른 작업이 같이 등록돼 있습니다.
- **네이버 요청 간격을 줄이지 마세요.** `study.mjs` 의 `GAP`(0.6초)과 `TOP_N`(10)은
  남의 서버에 부담을 주지 않는 선입니다.
- **카드 렌더는 `blog/` 안에서 따로 합니다.** `studio/카드뉴스/cardnews-white` 는 인스타 세로형
  전용이고 crontab 이 도는 운영 코드라 건드리지 않습니다.
- **블로그 자동화가 하나 더 있습니다.** `_공용/content-pipeline/post-generator/blog-daily.mjs` 가
  월·수·금 아침에 **뉴스 소재로** 5계정 초안을 만듭니다. 이쪽은 **검색 유입**이 목적이라 축이 다릅니다.
